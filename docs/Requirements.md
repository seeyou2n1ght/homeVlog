# HomeVlog 项目业务需求与约束条件说明书

## 1. 核心业务背景与目标
本项目（HomeVlog）是一个专门针对家庭安防监控设备产出的海量监控视频素材，进行“智能浓缩”处理的离线跑批系统。
核心目标是剔除监控视频中无价值的长时间静止画面，保留包含人、宠物、车辆等动态事件的片段，最终合成一段连贯且无缝拼接的浓缩版 Vlog 视频，极大降低人工筛选视频的时间成本。

## 2. 核心功能需求

### 2.1 素材生命周期与调度
- **扫描发现（Scan）**：针对指定的局域网 SMB 共享路径（如 `\\192.168.5.8\LyuShare`），按照特定正则匹配摄像头目录（`XiaomiCamera_<index>_<mac>`），识别内部的 `.mp4` 文件。
- **元数据提取**：基于文件命名规则（`00_YYYYMMDDHHMMSS_YYYYMMDDHHMMSS.mp4`）提取视频起止时间戳，并结合摄像头 MAC 地址记录入 SQLite 数据库，建立结构化的索引。
- **日期与设备隔离**：支持多摄像头并发录像提取。必须根据配置文件中定义的字典映射（如 `B888806BD537` 映射为 `cam_alias`），按日期和摄像头生成独立的浓缩产物输出。

### 2.2 智能浓缩算法需求
- **静止段（STATIC）处理**：当监控画面无有价值物体移动时，必须大幅剔除帧率（极速快进），仅抽取极其少量的关键帧作为时间流逝的过度，保持视觉连续性。
- **运动段（DYNAMIC）处理**：当监测到实体移动时，必须保持原速（1.0x）及原音轨输出，不丢失任何事件细节。
- **运动识别双重校验**：
  - 第一层（能量差）：利用帧间像素绝对差值（加入高斯去噪平滑底噪）进行动态能量潮汐检测。
  - 第二层（语义验证）：对判定为静止边缘或能量不明显但存疑的片段，需通过 YOLO（如 `yolo11n`）执行目标检测（人、猫、狗等），修正由于物体缓慢移动造成的漏报。

### 2.3 渲染引擎需求
- 接收分析器传递的时间轴剪辑片段（Timeline Segments），组装为复杂的 FFmpeg Filter Graph。
- 全程自动判断是否有音轨，根据动静状态对视频流应用 `trim`、`setpts`，对音频流应用 `atrim`、`asetpts`。

## 3. 核心技术约束条件

### 3.1 极限硬件调度约束
- **零拷贝（Zero-IO）与单次解码**：遵循“一次解码，多重消费”哲学。禁止在分析阶段产生任何中间临时文件落盘，PyAV 解码出的帧必须直接在内存字典和显存间流转并同步提供给 OpenCV 能量分析与 YOLO 推理使用。
- **显存与带宽控制**：神经网络推理必须全面启用 FP16（半精度计算），最大限度减少显存带宽开销占用。
- **硬件锁（Semaphores）机制**：严格控制并发行程。必须根据设备环境配置针对 NVENC 和 QSV 硬件编码器施加独立并发数限制（例如 3060Ti 的 NVENC 并发墙），防止驱动级崩溃。

### 3.2 容错与网络环境约束
- **防假死机制**：由于原始素材大多挂载于 NAS 上，网络波动和 I/O 抖动为常态。禁止使用阻塞式的探针（如子进程运行 `ffprobe`），所有元数据探测需采用 PyAV 懒加载读取。
- **损坏跳过与不宕机**：针对因断电、截断导致的破损 `.mp4` 文件，底层需捕获解码器抛出的异常，记录日志并安全跳过。无论缺失多少微小片段，必须保证最终能拼接出最终的 Vlog 文件。

### 3.3 工程架构与编码约束
- **环境隔离**：必须强制使用 `uv` 作为包与环境管理工具。
- **防御性编程**：所有业务函数和核心算法层必须具有严格的类型注解（Type Hints）与边界条件异常捕捉（如被除数为 0、空数组切片）。
- **可观测性**：基于 `loguru` 构建现代、无阻塞且带有颜色分级和按日志文件回滚切分的追踪日志。杜绝随意 `print` 导致的标准输出污染。
- **时间轴闭环**：早停算法（Early Termination）在切断解码循环时，计算出的视频逻辑终止时间点必须与视频头部物理偏移精确对接，严格杜绝最终合成视频出现“跳秒”和“音频丢包”问题。
